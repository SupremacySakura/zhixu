# 术语表（GLOSSARY）

本仓库的领域术语，只记录「词叫什么、指什么、代码里叫什么」，不写实现细节与决策理由（决策见 [docs/adr/](./docs/adr/)）。
议题标题、重构提案、测试名称中提到领域概念时使用这里的译名，不要另造同义词。

## 知识管理

| 术语         | 含义                                                       | 代码标识                                  |
| ------------ | ---------------------------------------------------------- | ----------------------------------------- |
| 知识条目     | 用户录入或导入的一条知识，是知识库的最小可检索单位         | `knowledge_items` / `KnowledgeItem`       |
| 分块         | 知识条目按标题层级切出的片段，是向量化与检索的粒度         | `knowledge_chunks` / `KnowledgeChunk`     |
| 分块序号     | 分块在知识条目内的顺序号，从 1 开始，用于引用定位          | `seq`                                     |
| 知识来源类型 | 知识条目的录入方式：手动 / Markdown 文件 / PDF / 网页      | `source_type`: manual、markdown、pdf、web |
| 版本号       | 知识条目正文的乐观锁版本，每次正文更新加一                 | `version`                                 |
| 向量状态     | 分块向量化进度：未开始 / 排队中 / 进行中 / 就绪 / 部分失败 | `vector_state`                            |
| 归档         | 知识条目退出列表与检索可见性，但保留正文、分块与向量       | `archived_at`                             |

## AI 工作流

| 术语     | 含义                                                         | 代码标识                                   |
| -------- | ------------------------------------------------------------ | ------------------------------------------ |
| AI 任务  | 统一记录一次 AI 工作流执行的状态机行，是所有 AI 工作流的载体 | `ai_tasks` / `AiTask`                      |
| 任务类型 | AI 任务的种类：整理 / 关联 / 演化                            | `task_type`: organize、relation、evolve    |
| 整理草稿 | AI 整理产出但尚未被用户采纳的摘要、关键词、推荐标签          | `ai_tasks.payload` 内的 organize 草稿      |
| 采纳     | 用户确认（可编辑后）把整理草稿写入知识条目正式字段的动作     | `POST /knowledge/:id/organize/accept`      |
| 重新整理 | 丢弃现有草稿、重新执行一次 organize 任务                     | `POST /knowledge/:id/organize/regenerate`  |
| 重新查找 | 重新执行一次 relation 任务，增量补充建议关系                 | `POST /knowledge/:id/relations/regenerate` |
| 幂等键   | 同一任务类型对同一目标去重的键，只在任务未结束期间存在       | `ai_tasks.dedupe_key`                      |

## 知识关联

| 术语       | 含义                                                         | 代码标识                                                              |
| ---------- | ------------------------------------------------------------ | --------------------------------------------------------------------- |
| 关系       | 两个知识条目之间一条有向的语义联系                           | `knowledge_relations` / `KnowledgeRelation`                           |
| 关系类型   | 关系的语义种类，共六种：相关、依赖、补充说明、对比、更新替代、矛盾 | `relation_type`: related、depends_on、supplements、contrasts、updates、contradicts |
| 源头知识   | 关系的有向起点                                               | `source_id`                                                           |
| 目标知识   | 关系的有向终点                                               | `target_id`                                                           |
| 对称类型   | 方向无意义的关系类型：相关、对比；存一条即可                 | related、contrasts                                                    |
| 关系状态   | 建议 / 已确认 / 已拒绝三种状态                               | `status`: suggested、confirmed、rejected                              |
| 关联来源   | 关系由 AI 推荐还是用户手动建立                               | `source`: ai、manual                                                  |
| 建议关系   | AI 判定但用户尚未确认的关系，不计入图谱默认视图              | suggested                                                             |
| 已确认关系 | 用户确认过（或手动建立）的关系，是图谱的数据来源             | confirmed                                                             |
| 建议抑制   | 用户拒绝过的知识对不再被推荐，靠保留 rejected 行实现         | rejected + 唯一键                                                     |
| 关系证据   | AI 给出的判定依据：理由 + 源头引文 + 目标引文                | `evidence`: reason、source_quote、target_quote                        |
| 候选知识   | 送交 AI 判定关系的近邻知识条目，最多十条                     | relation 请求的 `candidates`                                          |

## 知识图谱

| 术语     | 含义                                           | 代码标识       |
| -------- | ---------------------------------------------- | -------------- |
| 局部图谱 | 以某个知识条目为中心、只展开一跳邻居的图谱视图 | `depth=1`      |
| 中心节点 | 局部图谱的起点知识条目                         | `center_id`    |
| 图谱截断 | 节点数超过上限时按连接度裁剪，并在响应中标记   | `truncated`    |
| 图谱边   | 图谱中的一条关系，默认只画已确认关系           | 关系行渲染而成 |

## 知识演化

| 术语     | 含义                                                             | 代码标识                                                                              |
| -------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 演化提醒 | AI 对知识之间关系或时效性的审计结论，等待用户裁决                | `evolution_alerts` / `EvolutionAlert`                                                |
| 提醒类型 | 演化提醒的三种结论：重复、过时、冲突                             | `alert_type`: duplicate、outdated、conflict                                           |
| 提醒状态 | 待处理 / 已处理 / 已忽略 / 暂不处理                              | `status`: pending、resolved、dismissed、deferred                                      |
| 提醒严重度 | 提醒的证据强度：建议复核、强烈建议复核                         | `severity`: review、strong                                                            |
| 证据引文 | AI 判定时引用的知识原文片段，必须能在该知识正文中定位            | `evidence[]`: knowledge_id、quote                                                     |
| 裁决动作 | 用户处理演化提醒的六种方式                                       | `action`: accept_revision、keep_both、archive_one、create_relation、mark_outdated、mark_verified |
| 过时标记 | 知识条目被确认可能过时的理由，不影响其可检索性                   | `outdated_at`、`outdated_reason`                                                     |
| 正文指纹 | 知识正文规范化后的哈希，用于精确重复检测                         | `content_hash`                                                                        |
| 重新检查 | 对某条知识手动重跑一次演化检查                                   | `POST /knowledge/:id/evolve/regenerate`                                               |

## 不使用的说法

- 不要用「引用关系」「链接」指代**关系**：关系是知识之间的语义联系，引用是回答中的出处（见检索问答的引用溯源）。
- 不要用「节点」指代非图谱语境下的**知识条目**；节点只在图谱视图里使用。
- 不要用「隐藏」「删除」描述**建议抑制**：拒绝不删行，只是不再推荐同一对。
- 不要用「标签推荐」指代**关联推荐**：前者是 organize 的 suggestedTags，后者是 relation。
- 不要用「对比」指代**矛盾**：对比（contrasts）是两种可选视角，矛盾（contradicts）是对同一事实的互斥结论。
- 不要用 `potential_conflict` 指代**冲突提醒**：提醒类型只有 conflict，潜在性是判定的过程而非结果。
- 不要用「合并」指代**归档其一**：重复提醒的裁决是保留一条、归档另一条，不做正文合并。
