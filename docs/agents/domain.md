# 领域文档

工程技能探索代码库时，应如何使用此仓库的领域文档。本仓库为**单上下文**布局。

## 探索之前，请阅读

- 仓库根目录的 **`GLOSSARY.md`**。
- **`docs/adr/`**：阅读涉及即将处理区域的 ADR。

若这些文件不存在，**默默继续**。不要指出它们缺失，也不要建议提前创建。`/domain-modeling` 会在术语或决策明确时按需创建。

## 文件结构

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-....md
│   └── 0002-....md
└── apps/
    ├── zhixu-frontend/
    ├── zhixu-backend/
    └── zhixu-ai/
```

三个应用（前端 Vue、后端 Go、AI Mastra）共用同一套领域概念（知识、分块、检索、AI 任务…），因此术语表只有根目录一份。

## 使用术语表中的术语

在议题标题、重构提案、假设、测试名称等输出中提到领域概念时，使用 `GLOSSARY.md` 定义的术语，不要改用术语表明确要求避免的同义词。若所需概念尚未收录，说明可能是在发明项目不使用的语言（重新考虑），或确有缺口（记录下来交给 `/domain-modeling`）。

## 指出 ADR 冲突

输出与现有 ADR 冲突时明确指出，不要默默覆盖：_与 ADR-0007（……）冲突，但值得重新讨论，因为……_

## 与其他知识层的关系

`docs/brain/`（项目全局认知）与 `docs/tasks/`（任务教训）是另一套知识层，按根 `AGENTS.md` 的 AI 读取协议使用，与术语表/ADR 不重复。
