## 一、引言

### 1.1 编写目的

本文档将《产品设计文档》中的功能设想细化为实现层面可执行、可测试、可验收的需求条目。每个功能需求均包含编号、优先级、输入、输出、业务规则、异常情况和验收标准，作为以下工作的依据：

- 开发实现与代码评审的验收依据。
- 毕设论文第三章"系统需求分析"的主要素材。
- 后续测试计划与实验评估的执行基础。

### 1.2 项目范围

系统覆盖个人知识的采集、整理、检索、关联与演化全生命周期，包含六大功能模块：知识管理、AI 智能整理、智能检索与问答、知识关联、知识演化、系统管理。

不在本期范围内：多人协作、组织管理、复杂工作流编辑器、自动批量改写旧知识、微服务集群、多 Agent 自主协作、外部知识自动爬取更新。

### 1.3 术语与定义

| 术语          | 定义                                                     |
| ----------- | ------------------------------------------------------ |
| LLM         | 大语言模型，用于摘要生成、问答、关联判断、演化分析等任务                        |
| RAG         | 检索增强生成，先检索个人知识库再基于检索结果生成答案                          |
| Embedding   | 文本向量，用于语义相似度计算                                        |
| 分块（Chunk）   | 知识正文按策略切分后的片段，是向量化和检索的最小单元                          |
| 混合检索        | 关键词检索与向量语义检索并行执行、合并重排的检索方式                           |
| 知识演化        | 对库内重复、冲突、可能过时的知识进行检测、提醒与修订的机制                        |
| Qdrant      | 向量数据库，用于存储和检索 Embedding（由 AI 服务独占写入）        |
| SSE         | Server-Sent Events，用于 AI 问答的流式输出                 |
| 处理状态       | 知识异步处理流程的状态：待处理、处理中、就绪、失败                            |

## 二、项目概述

### 2.1 产品描述

知序（KnowledgeFlow）是一个以个人知识为核心的数据管理与智能处理系统。用户导入或创建知识后，系统自动完成分块、向量化、摘要与标签生成，并提供混合检索、带引用的 AI 问答、知识图谱可视化和知识演化提醒。

系统采用双服务架构（详见《架构设计方案-v2.md》）：Go 业务服务作为唯一对外网关与状态属主（鉴权、权限校验、任务状态机、会话持久化），Mastra 以独立服务模式运行 AI 工作流（文档解析、分块、Embedding、整理/问答/关联/演化编排），Vercel AI SDK 负责模型调用与结构化输出，MySQL 8 存储业务数据（ngram 全文索引支持关键词检索），Qdrant 存储向量，本地文件存储保存原始文件。

### 2.2 用户角色

系统只设一种角色：**注册用户**。所有数据严格按用户隔离，不存在跨用户共享数据。毕设场景下由同一人使用多个账号即可完成多用户相关验证。

### 2.3 功能需求总览

| 编号前缀     | 模块       | 功能数 | 需求条目                       |
| -------- | -------- | --- | -------------------------- |
| FR-KM    | 知识管理     | 9   | 创建编辑、文件导入、网页导入、列表、详情、分类标签、收藏归档、分块预览、编辑历史 |
| FR-ORG   | AI 智能整理  | 6   | 触发整理、摘要、关键词概念、标签推荐、结果确认、相关知识发现      |
| FR-QA    | 智能检索与问答  | 7   | 关键词检索、语义检索、混合检索、AI 问答、引用溯源、拒答、会话历史  |
| FR-REL   | 知识关联     | 3   | 关联推荐、关系管理、图谱可视化              |
| FR-EVO   | 知识演化     | 5   | 重复检测、过时识别、冲突识别、版本管理、审核处理             |
| FR-SYS   | 系统管理     | 6   | 注册登录、数据隔离、模型配置、任务管理、失败重试、用量统计       |

### 2.4 设计约束

1. 采用双服务架构：Go 业务服务 + Mastra AI 计算服务；AI 服务仅内部可达（共享密钥鉴权），不直接对外暴露。
2. AI 生成的任何内容不得自动覆盖用户原始知识，重要变更必须经用户确认。
3. 模型 API 密钥仅保存在服务端，不得下发到浏览器。
4. 所有 AI 调用采用结构化输出并进行 Schema 校验。
5. 固定流程由确定性代码控制，仅在需要模型理解、判断、生成的环节调用 LLM。

### 2.5 假设与依赖

1. 系统依赖第三方 LLM 与 Embedding 服务（OpenAI 兼容接口），部署环境可访问对应 API。
2. Embedding 模型维度确定后不再变更；如变更，需对全库向量重建并重新分块。
3. 部署目标环境支持 Docker，具备 MySQL 8 与 Qdrant。
4. 用户使用现代浏览器（见 4.5 节）。

## 三、功能需求

需求条目格式说明：**优先级**中"高"对应产品设计文档第十二章"必须完成"，"中"对应"重点特色"，"低"为增强功能。

### 3.1 知识管理模块（FR-KM）

#### FR-KM-01 知识的创建与编辑

- **优先级**：高（MVP 必须）
- **描述**：用户手动创建知识条目，以 Markdown 编辑标题与正文，支持后续修改。
- **前置条件**：用户已登录。
- **输入**：标题（必填，1–200 字符）、正文（Markdown，建议非空）、分类、标签、`source_type = manual`。
- **处理规则**：
  1. 服务端校验字段合法性与长度限制，非法输入拒绝写入并返回明确错误。
  2. 创建后写入 `knowledge_items`，初始处理状态为"待处理"。
  3. 创建/编辑成功后自动触发异步处理（分块、向量化），见 FR-SYS-04。
  4. 正文修改后，作废旧分块及向量并重新生成；AI 摘要与标签不受影响，除非用户重新触发整理。
- **输出**：知识详情页；列表中出现新条目或更新标记。
- **异常情况**：标题为空或超长 → 拒绝提交并提示；正文超过单条长度上限（200k 字符）→ 提示改用文件导入。
- **验收标准**：
  - 合法输入创建后可在列表和详情页查看；
  - 正文修改后，分块预览页展示的是最新分块；
  - 未登录请求创建接口返回 401。

#### FR-KM-02 文件导入（Markdown / PDF）

- **优先级**：高（MVP 必须）
- **描述**：用户上传 `.md` / `.markdown` / `.pdf` 文件，系统解析正文并入库，原始文件存档。
- **输入**：单个文件，大小上限 20MB。
- **处理规则**：
  1. 校验扩展名与大小，通过后保存原始文件至文件存储，并记录存储路径。
  2. 解析正文：Markdown 保留原文结构；PDF 提取文本层并尽量保留页码信息写入分块 metadata。
  3. 标题默认取文件名，允许导入后修改。
  4. 解析成功后按 FR-KM-01 规则进入异步处理流程；`source_type` 标记为 `markdown` 或 `pdf`。
- **输出**：导入结果反馈（成功条数、失败原因）；知识列表新增条目。
- **异常情况**：不支持的格式 → 拒绝并提示；PDF 无文本层（扫描件）→ 解析失败提示；解析过程出错 → 保留原始文件，条目进入"失败"状态，支持重试（FR-SYS-05）。
- **验收标准**：
  - 导入 Markdown 文件后正文格式完整可读；
  - 导入含文本层的 PDF 后正文可检索，分块带页码元数据；
  - 扫描版 PDF 导入时给出明确失败原因。

#### FR-KM-03 网页导入

- **优先级**：高（MVP 必须）
- **描述**：用户提交 URL，服务端抓取网页并提取正文保存，同时记录来源地址。
- **输入**：合法的 http/https URL。
- **处理规则**：
  1. 服务端抓取页面，提取正文（去除导航、广告、页脚等噪声）。
  2. 网页标题作为知识标题，正文存入 `content`，原始 URL 存入 `source_url`，`source_type = web`。
  3. 进入异步处理流程。
- **输出**：导入成功提示与知识条目；失败时展示失败原因。
- **异常情况**：URL 无法访问或超时（10 秒）→ 导入失败提示；页面无法提取有效正文（如纯图片页）→ 提示"未能提取到正文"。
- **验收标准**：
  - 常见技术博客页面可提取出可读正文；
  - 详情页可查看并跳转原始来源 URL。

#### FR-KM-04 知识列表

- **优先级**：高（MVP 必须）
- **描述**：分页展示当前用户的全部知识，支持筛选、排序与搜索入口。
- **输入**：筛选条件（来源类型、标签、处理状态、收藏/归档）、排序（更新时间、创建时间、标题）、页码。
- **处理规则**：
  1. 列表仅返回当前用户数据，默认每页 20 条。
  2. 每条展示标题、来源类型、标签、更新时间、处理状态标识。
  3. 列表内搜索为关键词匹配（标题与正文），完整检索能力见 FR-QA。
- **输出**：分页列表。
- **异常情况**：无数据时展示空状态与"新建/导入"引导。
- **验收标准**：筛选、排序、分页结果正确；不同用户互不可见对方条目。

#### FR-KM-05 知识详情

- **优先级**：高（MVP 必须）
- **描述**：展示单条知识的正文（Markdown 渲染）、AI 摘要、标签、关联知识入口、版本入口与分块预览入口。
- **输入**：知识 ID。
- **处理规则**：
  1. 校验知识存在且属于当前用户，否则返回 404。
  2. 正文以渲染后的 Markdown 展示，保留原文不可变；摘要、标签区与正文区视觉分区。
  3. 页面提供编辑、触发整理、查看分块、查看版本、查看关联的操作入口。
- **输出**：详情页。
- **异常情况**：知识不存在或无权访问 → 404。
- **验收标准**：页面信息完整，原文与 AI 元数据分区清晰。

#### FR-KM-06 分类与标签管理

- **优先级**：高（MVP 必须）
- **描述**：用户可创建、重命名、删除标签，为知识打标签；分类支持单层管理。
- **输入**：标签名称（去重）、知识-标签关联操作。
- **处理规则**：
  1. 标签按用户隔离，同用户下名称唯一（不区分大小写）。
  2. 一条知识可挂多个标签；`knowledge_tags.source` 记录 `manual` 或 `ai`。
  3. AI 推荐的标签在用户确认前不写入关联表。
  4. 删除标签时解除全部关联；删除分类下知识自动移出该分类。
- **输出**：标签列表；知识上的标签展示。
- **异常情况**：重名标签 → 提示复用已有标签。
- **验收标准**：标签增删改查正确；AI 标签来源可区分。

#### FR-KM-07 收藏与归档

- **优先级**：中（可选）
- **描述**：支持收藏常用知识与归档暂不使用的知识。
- **处理规则**：
  1. 收藏的知识在首页与列表中优先展示。
  2. 归档知识默认不出现在列表与检索结果中；AI 问答检索默认排除归档知识，用户可在问答时手动选择"包含归档"。
  3. 归档与收藏互不影响，可随时恢复。
- **输出**：列表筛选项"已归档"；首页收藏区。
- **验收标准**：归档知识默认不参与问答检索；取消归档后恢复正常。

#### FR-KM-08 分块预览

- **优先级**：中（可选，建议实现）
- **描述**：提供独立页面展示每条知识经文本切分后的实际结果（对应产品设计文档 3.2 节）。
- **输入**：知识 ID。
- **处理规则**：
  1. 按 `chunk_index` 顺序展示各分块内容、字符数与 metadata（页码、标题路径）。
  2. 展示每个分块的向量化状态与索引状态。
  3. 支持从 AI 问答引用跳转到本页并高亮对应分块（与 FR-QA-05 联动）。
  4. 支持对单条知识手动触发重新分块与向量化，完成后刷新展示。
- **输出**：分块预览页。
- **异常情况**：知识尚无分块（处理失败或排队中）→ 展示处理状态提示。
- **验收标准**：分块内容与顺序和 `knowledge_chunks` 表一致；引用跳转高亮定位准确。

#### FR-KM-09 编辑历史

- **优先级**：低（增强）
- **描述**：查看知识的修改记录，与版本表（FR-EVO-04）共用数据结构。
- **处理规则**：每次手动保存或采纳 AI 修订前生成一条版本快照（标题、正文、`change_source`）。
- **验收标准**：历史版本可按时间查看，内容快照准确。

### 3.2 AI 智能整理模块（FR-ORG）

#### FR-ORG-01 触发智能整理

- **优先级**：高（MVP 必须）
- **描述**：知识创建或导入后自动进入整理队列，用户也可对单条知识手动重新触发。
- **处理规则**：
  1. 同一知识同一时间最多一个运行中的整理任务（幂等约束）。
  2. 任务写入 `ai_tasks`（`task_type = summarize`），状态流转见 FR-SYS-04。
  3. 整理任务与分块/向量化任务相互独立，互不等候。
- **异常情况**：模型调用超时 → 任务标记失败，可重试（FR-SYS-05）。
- **验收标准**：重复触发不产生并行任务；任务状态对用户可见。

#### FR-ORG-02 摘要生成

- **优先级**：高（MVP 必须）
- **描述**：为知识生成一段简洁摘要，存于 `knowledge_items.summary`。
- **输入**：知识正文（超长时按分块截取重点内容）。
- **处理规则**：
  1. 通过 LLM 结构化输出生成摘要，长度约束在 200 字以内。
  2. 返回结果经 Schema 校验，不合规视为任务失败。
  3. 摘要只写入 summary 字段，绝不修改原始正文。
- **输出**：摘要文本。
- **异常情况**：Schema 校验失败、模型超时 → 任务失败，保留原文。
- **验收标准**：生成摘要通顺且与正文主题一致；摘要更新不影响正文与分块。

#### FR-ORG-03 关键词与核心概念提取

- **优先级**：高（MVP 必须）
- **描述**：提取 3–8 个关键词和若干核心概念，用于展示与检索辅助。
- **处理规则**：
  1. 结构化输出 keywords 与 concepts 列表，Schema 校验。
  2. 结果随整理结果一并展示，用户确认后生效。
- **验收标准**：关键词与正文相关，无重复项与空值。

#### FR-ORG-04 标签推荐

- **优先级**：高（MVP 必须）
- **描述**：基于内容推荐已有标签，必要时建议新标签。
- **处理规则**：
  1. 优先从当前用户已有标签中推荐，语义接近的标签不重复推荐。
  2. 确有必要时才建议创建新标签，并明确标注"新标签"供用户选择。
  3. 用户勾选确认后写入 `knowledge_tags`，`source` 按人工/AI 分别记录（用户调整过的按用户确认结果记录）。
- **验收标准**：推荐标签与内容相关；不会出现大量同义新标签。

#### FR-ORG-05 整理结果预览与确认

- **优先级**：高（MVP 必须）
- **描述**：AI 整理结果（摘要、关键词、推荐标签）先展示预览，用户确认或修改后生效。
- **处理规则**：
  1. 未确认前 AI 结果不作为正式元数据展示于详情页主区域，仅标记"待确认"。
  2. 用户可编辑摘要、调整关键词、勾选/取消标签后保存。
  3. 用户可选择"重新生成"再次调用模型。
- **验收标准**：未经确认的结果不进入正式元数据；编辑保存后生效。

#### FR-ORG-06 相关知识初步发现

- **优先级**：高（MVP 必须，与 FR-REL-01 联动）
- **描述**：整理完成后自动触发一次关联候选检索，结果交由知识关联模块生成推荐。
- **处理规则**：以当前知识向量检索 Top 20 近邻作为候选，交 FR-REL-01 判定。
- **验收标准**：新知识导入后能在关联推荐中看到候选条目。

### 3.3 智能检索与 AI 问答模块（FR-QA）

#### FR-QA-01 关键词检索

- **优先级**：高（MVP 必须）
- **描述**：基于关键词匹配标题与正文的传统检索。
- **处理规则**：
  1. 采用 MySQL 8 ngram 分词器的全文索引（选型决策见架构方案 v2.1 D3）。
  2. 检索范围限定当前用户，默认排除归档知识。
  3. 返回知识 ID、标题、命中片段与相关度。
- **验收标准**：输入确切存在的关键词能命中对应知识；不会返回其他用户的数据。

#### FR-QA-02 语义检索

- **优先级**：高（MVP 必须）
- **描述**：将查询文本向量化，在 Qdrant 中检索语义最近的分块。
- **处理规则**：
  1. 查询与分块使用同一 Embedding 模型。
  2. 返回 Top K（默认 20，可调）分块及其所属知识，携带 `chunk_id` 与 `knowledge_id`。
  3. 必须附加 `user_id` 过滤条件，禁止跨用户检索。
- **验收标准**：语义相近但措辞不同的问题能召回相关分块；向量检索结果均属于当前用户。

#### FR-QA-03 混合检索与重排

- **优先级**：高（MVP 必须）
- **描述**：关键词检索与语义检索并行执行，合并去重后重排，产出最终候选集。
- **处理规则**：
  1. 采用 RRF（倒数排名融合）或加权打分合并两路结果。
  2. 重排后取 Top N（默认 5–10）作为问答上下文候选。
  3. 每路检索独立失败时降级为单路结果并记录日志，两路均失败时返回检索失败提示。
- **验收标准**：同一问题下混合检索结果质量不低于任一单路（以 9.1 节实验指标衡量）。

#### FR-QA-04 AI 问答

- **优先级**：高（MVP 必须）
- **描述**：用户以自然语言提问，系统基于个人知识库生成带引用的流式回答，并保存会话。
- **输入**：问题文本（必填，≤ 2000 字符）、可选会话 ID。
- **处理规则**：
  1. 对问题进行必要的查询改写（可选步骤）。
  2. 执行 FR-QA-03 混合检索，判断证据充分性（FR-QA-06）。
  3. 将候选分块组装为上下文，要求模型仅依据上下文作答，并以结构化方式输出引用 ID。
  4. 回答通过 SSE 流式返回；会话与消息写入 `chat_sessions` / `chat_messages`。
  5. 生成前对引用做服务端校验（FR-QA-05），校验失败则降级为不带引用的回答并标注。
- **输出**：流式答案文本、引用列表、相关分块信息。
- **异常情况**：模型超时 → 返回友好错误，会话保留用户问题；检索结果为空 → 进入拒答流程。
- **验收标准**：回答基于库内知识生成；无证据时不编造事实；流式输出过程无明显卡顿。

#### FR-QA-05 引用与溯源

- **优先级**：高（MVP 必须）
- **描述**：回答中的引用必须指向真实检索到的知识与分块，支持点击溯源。
- **处理规则**：
  1. 检索结果携带稳定的 `knowledge_id` 与 `chunk_id`，模型被要求引用这些 ID。
  2. 服务端解析引用 ID 并校验其存在于本次检索结果中且属于当前用户；校验不通过的引用剔除。
  3. 前端将引用渲染为可点击卡片，跳转知识详情或分块预览并高亮对应分块。
  4. 引用信息持久化到消息记录，不能只保存模型生成的文本链接。
- **验收标准**：每条引用均可打开到真实知识内容；伪造或不存在的引用不会展示给用户。

#### FR-QA-06 知识不足拒答

- **优先级**：高（MVP 必须）
- **描述**：证据不足时明确拒答，不生成无依据内容。
- **处理规则**：
  1. 当 Top N 结果相似度均低于阈值（默认 0.5，可调）或判定不相关时，判定证据不足。
  2. 返回固定话术，如"知识库中未找到足够相关的信息，试试换个问法或先导入相关资料"。
- **验收标准**：对库中不存在的话题提问时系统拒答而非编造。

#### FR-QA-07 会话历史

- **优先级**：低（增强）
- **描述**：保存问答会话列表，支持查看历史会话与继续提问。
- **处理规则**：会话按用户隔离；支持删除会话及其消息。
- **验收标准**：历史会话可回放，引用仍可跳转。

### 3.4 知识关联模块（FR-REL）

#### FR-REL-01 关联推荐

- **优先级**：高（MVP 必须）
- **描述**：为知识推荐可能相关的条目，并给出关系类型与依据。
- **输入**：目标知识 ID；候选来自向量近邻（FR-ORG-06）。
- **处理规则**：
  1. 候选集经相似度阈值过滤后交由 LLM 判断关联类型与理由。
  2. 关系类型枚举：`related`（相关）、`depends_on`（依赖于）、`supplements`（补充说明）、`contrasts`（对比于），支持扩展。
  3. 每条推荐写入 `knowledge_relations`，`status = suggested`，附 `confidence` 与 `evidence`（含双方引文）。
  4. 关系表对（source_id, target_id, relation_type）建唯一约束，防重复插入。
- **输出**：待确认的关系建议列表。
- **异常情况**：模型输出不合 Schema → 丢弃该候选并记录日志。
- **验收标准**：推荐结果含类型、理由与证据；不产生重复关系。

#### FR-REL-02 关系管理

- **优先级**：高（MVP 必须）
- **描述**：用户对推荐关系执行确认、拒绝、删除，也可手动创建关系。
- **处理规则**：
  1. 确认后 `status = confirmed`；拒绝后 `status = rejected`，不再重复推荐同一关系。
  2. 手动创建关系需填写类型，直接置为 confirmed。
  3. 删除关系为物理删除，需二次确认。
- **验收标准**：三种操作及手动创建均正确落库；已拒绝的关系不再出现。

#### FR-REL-03 知识图谱可视化

- **优先级**：中（重点特色）
- **描述**：以图形式展示知识节点与已确认关系，支持交互。
- **处理规则**：
  1. 节点为知识，边为 confirmed 关系（可切换显示 suggested）。
  2. 默认展示当前选中知识的一度关系（局部视图），节点过多时按需加载，不一次性渲染全图。
  3. 点击节点打开详情；边展示关系类型与来源（AI 推荐/人工创建）。
  4. 提供按标签、来源类型筛选。
- **验收标准**：局部渲染流畅（100 节点内无卡顿）；交互操作可用。

### 3.5 知识演化模块（FR-EVO）

#### FR-EVO-01 重复知识检测

- **优先级**：中（重点特色）
- **描述**：新知识入库后检测可能重复的已有条目，交由用户判断合并。
- **触发方式**：导入/创建后自动触发 + 演化中心手动触发；为独立工作流，不做全库定时扫描。
- **处理规则**：
  1. 以新知识的向量近邻加标题相似度取候选。
  2. 由 LLM 对比内容输出相似度判断与差异说明，结构化校验。
  3. 疑似重复项进入演化中心待审核列表，展示两条知识的标题、相似度与差异摘要。
- **输出**：重复提醒条目（类型 `duplicate`）。
- **验收标准**：在人工标注测试集上 Precision ≥ 0.8、F1 ≥ 0.75（目标值，实验可校准）。

#### FR-EVO-02 潜在过时识别

- **优先级**：中（重点特色）
- **描述**：发现可能存在时效风险的知识并提示复核。
- **处理规则**：
  1. 依据版本信息、时间信息与内容差异生成提示，输出须包含可解释证据（如"新资料提到不同 API 用法"）。
  2. 仅时间较早不构成提醒理由；无明确证据时仅生成低等级提示或不提示。
  3. 提醒等级分为"建议复核"与"强烈建议复核"，由证据强度决定。
- **输出**：过时风险提醒（类型 `outdated`），含证据引文。
- **验收标准**：每条提醒均可查看具体证据；无证据不产生高等级提醒。

#### FR-EVO-03 冲突识别与修订建议

- **优先级**：中（重点特色）
- **描述**：识别两条知识间的矛盾，展示原文证据并生成修改建议。
- **处理规则**：
  1. LLM 对比候选知识对，输出 `potential_conflict` 类型结果，结构含 `reason`、`evidence`（双方 `knowledgeId` + 原文引文）、`suggestedAction`。
  2. 服务端校验 evidence 中的知识 ID 存在、属于当前用户且引文能在原文中定位；校验失败则降级为仅提示不生成建议。
  3. 修订建议以差异对照形式展示，不直接改写原文。
- **输出**：冲突提醒（类型 `conflict`）与修订建议草稿。
- **异常情况**：引用无法定位 → 记录日志并降级处理。
- **验收标准**：冲突提示附双方原文证据；建议内容与差异一致；误报率在实验中可测量。

#### FR-EVO-04 版本管理

- **优先级**：中（重点特色）
- **描述**：知识修改前保留旧版本快照，支持查看与恢复。
- **处理规则**：
  1. 手动保存修改或采纳 AI 修订前，将当前标题与正文快照写入 `knowledge_versions`，记录 `change_source`（manual/ai）与版本号。
  2. 版本列表按时间倒序展示，可查看任意版本全文。
  3. 支持"基于此版本恢复"：将旧版本内容生成新版本（新版本号），不物理回滚历史。
- **验收标准**：每次变更前均有对应快照；恢复操作生成新版本而非覆盖。

#### FR-EVO-05 演化提醒审核

- **优先级**：中（重点特色）
- **描述**：演化中心集中展示重复、过时、冲突三类提醒，用户逐项处理。
- **处理规则**：
  1. 每条提醒支持操作：采纳（冲突时按建议创建新版本，见 FR-EVO-04）、忽略、暂不处理、标记已核实。
  2. 处理后记录处理人与处理方式；已核实/忽略的提醒不再重复弹出，同证据再次触发时除外。
  3. 全部处理动作只影响目标知识，绝不自动修改其他知识。
- **验收标准**：四种操作可用且留痕；采纳建议后原文未丢失、新版本可查看。

### 3.6 系统管理模块（FR-SYS）

#### FR-SYS-01 注册与登录

- **优先级**：高（MVP 必须）
- **描述**：邮箱 + 密码注册登录，会话由成熟认证方案（Auth.js 或等价）管理。
- **处理规则**：
  1. 密码以 Argon2/bcrypt 哈希存储，禁止明文与可逆加密。
  2. 密码强度要求：至少 8 位且包含字母与数字。
  3. 登录态过期后自动跳转登录页。
- **异常情况**：邮箱已注册 → 提示登录；密码错误 → 通用错误提示，不泄露账号是否存在。
- **验收标准**：注册登录流程可用；密码不落明文。

#### FR-SYS-02 数据隔离与权限

- **优先级**：高（MVP 必须）
- **描述**：所有业务数据按用户隔离，全接口实施用户级权限校验。
- **处理规则**：
  1. 每个查询强制附加 `user_id` 条件，包括向量检索。
  2. 访问他人资源一律返回 404（不返回 403 以避免资源存在性泄露）。
  3. 服务端不信任前端传入的 user_id，以会话身份为准。
- **验收标准**：以用户 B 身份请求用户 A 的知识/任务/会话接口均返回 404。

#### FR-SYS-03 模型配置

- **优先级**：高（MVP 必须）
- **描述**：管理员（即用户本人）配置 LLM 与 Embedding 模型接入参数。
- **输入**：API Key、Base URL、模型名称、Embedding 维度。
- **处理规则**：
  1. API Key 仅保存于服务端（环境变量或加密存储），任何接口不得返回完整密钥。
  2. 提供"测试连接"功能，调用轻量接口验证配置可用。
  3. 更换 Embedding 模型时提示需重建向量。
- **验收标准**：配置保存后任务可正常调用；前端任何位置不暴露完整密钥。

#### FR-SYS-04 异步任务管理

- **优先级**：高（MVP 必须）
- **描述**：文档解析、分块、向量化、AI 整理、演化检查均走异步任务，状态对用户可见。
- **处理规则**：
  1. 任务状态机：`pending → running → success / failed`，持久化于 `ai_tasks`。
  2. MVP 采用数据库任务表 + 轮询消费，不引入独立消息队列。
  3. 前端展示排队中、处理中、成功、失败四种状态；知识列表以状态角标呈现。
- **验收标准**：长任务不阻塞页面其他操作；状态流转与表记录一致。

#### FR-SYS-05 任务失败与重试

- **优先级**：高（MVP 必须）
- **描述**：失败任务展示错误原因，支持针对性重试。
- **处理规则**：
  1. 失败后保留已入库的原始知识与已完成步骤的结果，仅重跑失败步骤。
  2. 同一任务重试具备幂等性：重试不产生重复分块、重复向量或重复关系。
  3. 错误信息面向用户可读（如"模型调用超时""PDF 解析失败"），同时记录技术日志。
- **验收标准**：人为制造失败后可在任务列表看到原因并重试成功；无重复数据产生。

#### FR-SYS-06 用量统计

- **优先级**：中（可选）
- **描述**：展示个人使用概况。
- **处理规则**：统计知识条目数、各来源导入数量、问答次数、任务成功/失败数；仅本人可见，不记录问题内容明细。
- **验收标准**：统计数据与数据库实际记录一致。

## 四、非功能需求

### 4.1 性能需求

| 编号    | 指标                | 目标值                        |
| ----- | ----------------- | -------------------------- |
| NFR-P1 | 常规页面首屏加载          | ≤ 2 秒（局域网部署环境）             |
| NFR-P2 | 关键词/语义检索响应       | ≤ 1.5 秒（1000 条知识规模）        |
| NFR-P3 | AI 问答首字响应         | ≤ 5 秒（流式输出）               |
| NFR-P4 | 10 页内 PDF 解析+分块+向量化 | ≤ 60 秒                    |
| NFR-P5 | 并发能力              | ≥ 10 并发用户正常使用             |
| NFR-P6 | 数据规模              | 单用户支持 ≥ 1000 条知识、≥ 20000 分块 |

### 4.2 安全需求

1. **认证与授权**：所有业务接口需登录访问；资源级权限校验见 FR-SYS-02。
2. **密钥管理**：模型 API 密钥仅服务端保存，接口永不返回完整密钥（FR-SYS-03）。
3. **注入防护**：全部数据库访问参数化；前端渲染用户内容时转义，防 XSS；配置 CSP。
4. **密码安全**：密码哈希存储，满足 FR-SYS-01 的强度要求。
5. **输入校验**：服务端为所有入口的唯一校验权威，前端校验仅改善体验。

### 4.3 可靠性需求

1. AI 任务失败可定位、可重试，重试具备幂等性（FR-SYS-05）。
2. 单步失败不影响已完成的其他步骤；原始知识在任何失败场景下不丢失。
3. 模型调用设置超时（默认 60 秒）与重试上限（默认 2 次）。

### 4.4 可维护性与可移植性

1. 双服务结构（Go 业务服务 + AI 计算服务），服务内业务边界清晰（知识、整理、检索、关联、演化、系统）。
2. 环境相关配置（数据库、密钥、模型）全部外置为环境变量。
3. 提供 Docker Compose 一键部署，支持本地与服务器环境。

### 4.5 易用性与兼容性

1. 界面遵循产品设计文档第五章：主要操作明确、AI 结果先预览后生效、异步状态可见。
2. 兼容 Chrome、Edge、Safari、Firefox 最近两个大版本。
3. 图谱节点过多时优先展示局部关系，不渲染全图（FR-REL-03）。

## 五、接口需求

### 5.1 用户界面

页面清单与交互以产品设计文档 5.2 节为准，共 9 个页面：首页、知识列表、知识详情、分块预览、导入页面、AI 问答、知识图谱、演化中心、系统设置。

### 5.2 外部服务接口

| 接口          | 用途              | 说明                          |
| ----------- | --------------- | --------------------------- |
| LLM Chat 接口 | 摘要、问答、关联与演化判断   | OpenAI 兼容 `/chat/completions`，支持 `response_format` 结构化输出 |
| Embedding 接口 | 查询与分块向量化       | OpenAI 兼容 `/embeddings`，维度与库表一致 |
| 网页抓取       | 网页导入（FR-KM-03） | 服务端 HTTP 抓取，10 秒超时        |

### 5.3 数据存储接口

MySQL 8 存储业务数据；Qdrant 存储向量与检索 payload（由 AI 服务独占写入）；文件存储（本地 Docker 卷）保存原始文件。表结构以产品设计文档第七章为准，实现期产出物理数据模型文档（MySQL 方言）。

### 5.4 通信协议

前后端采用 REST + JSON；AI 问答流式输出采用 SSE；文件上传采用 multipart/form-data。部署层由 Nginx 提供反向代理。

## 六、数据需求

### 6.1 核心实体

用户、知识条目、知识分块、标签、知识-标签关联、知识关系、知识版本、AI 任务、问答会话、问答消息、模型配置，共 11 类实体，逻辑设计见产品设计文档 7.2 节。

### 6.2 数据约束

1. 所有用户业务数据携带 `user_id` 并在查询时强制过滤。
2. 分块向量维度与 Embedding 模型一致，由配置约束。
3. 引用记录必须包含 `knowledge_id` 与 `chunk_id`。
4. 版本快照在修改前生成；删除知识时级联删除其分块、向量、关系与任务记录（版本快照保留策略实现期确定）。

## 七、验收标准

### 7.1 MVP 功能验收清单

| 编号   | 验收项              | 通过条件                                     |
| ---- | ---------------- | ---------------------------------------- |
| AC-01 | 用户登录与数据隔离       | 注册登录可用；跨用户访问任意资源返回 404（FR-SYS-02）       |
| AC-02 | 知识创建编辑管理        | 创建、编辑、列表、详情全流程可用；编辑后分块同步更新（FR-KM-01/04/05） |
| AC-03 | 三种来源导入          | Markdown、PDF（文本层）、网页均可导入并提取正文（FR-KM-02/03） |
| AC-04 | AI 摘要与标签        | 自动生成摘要与推荐标签，预览确认后生效，不改动原文（FR-ORG-02~05） |
| AC-05 | 混合检索            | 关键词+向量检索合并重排，结果限本用户（FR-QA-03）              |
| AC-06 | 带引用 AI 问答       | 回答流式输出；引用可溯源到真实知识与分块；证据不足时拒答（FR-QA-04/05/06） |
| AC-07 | 相关知识推荐          | 新知识导入后产生关联推荐，可确认/拒绝（FR-REL-01/02）           |
| AC-08 | 任务状态与异常处理       | 异步任务状态可见；失败有原因可重试且幂等（FR-SYS-04/05）          |
| AC-09 | 分块预览            | 分块内容、状态展示准确；引用可跳转高亮（FR-KM-08）              |

### 7.3 实验与评估要求

1. 准备人工标注测试集：检索评估问题 ≥ 30 条；演化评估样本（重复/冲突/过时）≥ 20 组。
2. 检索对比实验：关键词、纯向量、混合三组方案，记录 Recall@K、MRR、引用准确率、拒答表现。
3. 演化评估：记录重复识别 Precision/Recall/F1、冲突提示准确率、误报率、建议采纳率。
4. 实验结果记入论文第六章，作为创新点（产品设计文档 9.1–9.3）的验证材料。
