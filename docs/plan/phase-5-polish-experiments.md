# P5 收尾增强与实验

> 对应《产品设计文档》开发计划阶段 7。补齐零碎需求、跑论文实验、做性能压测。
> 前置依赖：P1~P4 全部完成（实验依赖功能就绪与埋点数据）。

## 工作项

### W5.1 模型"测试连接"（FR-SYS-03 收尾）

- **后端**：`POST /api/v1/settings/providers/:id/test`——用加密存储的 API Key 真实调用该供应商（GET models 或一次最小 generate），返回成功/失败与失败原因（网络/鉴权/模型不存在）；不持久化探测结果，可刷新重试。
- **前端**：设置页供应商表单"测试连接"按钮（[model-settings-frontend.md](../model-settings-frontend.md) 已预留该功能的待办记录），展示结果与耗时。
- **验收**：有效 Key 显示成功，无效 Key 显示明确失败原因。

### W5.2 用量统计补全（FR-SYS-06 收尾）

- **后端**：`GET /api/v1/dashboard/stats` 扩展——知识条目数（按 source_type 分组）、问答次数与 token 用量（聚合 `ChatTurnUsage`，按日趋势）、任务成功/失败数（导入/向量化/ai_tasks）、检索拒答次数（P2-W2.6 日志）。
- **前端**：Dashboard 增加知识/问答/任务卡片与近 7 日趋势图（复用现有图表组件）。
- **验收**：统计与真实数据一致（手工核对一次）。

### W5.3 检索实验（SRS 7.3，论文创新点 9.1）

- **数据集**：≥30 条标准问题，覆盖：精确术语（关键词优势）、语义改写（向量优势）、混合意图；每条标注应命中的知识/分块（ground truth）。
- **方法**：用 P2-W2.2 的三模式开关（keyword/semantic/hybrid）跑同一问题集，读取 `retrieval_logs` 计算：
  - Recall@K（K=1/3/5）、MRR；
  - 问答引用准确率（引用是否真正支撑答案，人工标注）；
  - 拒答正确率（无关问题被拒 / 相关问题不误拒）。
- **产出**：实验脚本（可重复跑）+ 结果表（写入论文实验章节素材，存放位置随论文仓库，不在本仓库）。
- **验收**：三组数据齐全，混合模式在综合指标上不低于任一单路（若低于需分析原因写进论文）。

### W5.4 关联推荐实验（论文创新点 9.2）

- **数据**：P3 积累的确认/拒绝记录 + 人工标注的应关联知识对。
- **指标**：Top-K 推荐准确率、关系分类准确率（对 confirmed 关系抽样人工核对类型）、人工确认率、无关关系比例。
- **验收**：指标可复算（脚本 + 原始记录）。

### W5.5 演化实验（SRS 7.3，论文创新点 9.3）

- **数据集**：≥20 组评估样本（构造重复对、新旧版本对、观点冲突对、无关对照对）。
- **指标**：重复识别 Precision/Recall/F1、冲突提示准确率、误报率、用户采纳率（从 evolution_alerts 的 resolve 记录统计）。
- **验收**：指标可复算；误报案例归档为论文分析素材。

### W5.6 性能压测（SRS 非功能需求）

- **项目**：语义检索 ≤2s、问答首 token ≤3s（P2 日志直接取数）；500 页 PDF 导入+向量化 ≤60s（造测试文件实测）；100 用户并发问答（k6/vegeta 打 `/v1/chat`，观察错误率与延迟分布）。
- **说明**：并发目标为毕业设计演示规模，不达标时记录瓶颈分析即可（论文可写优化方向）。
