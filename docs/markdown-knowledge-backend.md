# Markdown 文件加入知识库

## 数据库变化

后端启动时通过 GORM AutoMigrate 幂等补建两张表，不改变或清空现有文件表。

| 表 | 内容 | 约束 |
| --- | --- | --- |
| `knowledge_items` | 用户、标题、来源文件 ID、文件名/目录快照、来源哈希、Markdown 正文、状态、错误原因、入库时间 | `(user_id, source_file_id)` 唯一；用户/创建时间索引、状态索引 |
| `knowledge_import_tasks` | 知识 ID、用户、状态、尝试次数、处理租约与过期时间 | `knowledge_id` 唯一；状态/租约时间索引 |

- 首次提交在同一事务内创建条目和任务，状态均为 `pending`。正文初始为空。
- 原文件仍由 `file_models` 管理，不增加状态字段；没有级联删除关联。
- 来源快照保持不变。原文件改名或移动不重写知识来源快照；原文件软删除后，已导入正文仍可阅读。
- 一个逻辑文件对应一个知识条目。知识条目及任务使用物理删除，删除后可再次加入同一个仍存在的源文件；暂不支持新版本导入。
- 不新增版本、向量、分块或摘要表，也不调用 Mastra。
- 运行迁移的 MySQL 账号需有建表、建索引权限；任务领取使用 MySQL 8 的 `FOR UPDATE SKIP LOCKED`。

## 接口

以下为后端路径；前端通过 `/api` 代理访问。全部需要 `Authorization: Bearer <token>`，只能访问自己的文件和知识。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/knowledge` | 加入文件，JSON：`{"file_id": 123, "title": "可选标题"}` |
| GET | `/knowledge` | 分页列表：`page=1&page_size=20&q=标题&status=ready` |
| GET | `/knowledge/:id` | 详情、Markdown 原始正文、状态和错误原因 |
| GET | `/knowledge/by-file/:file_id` | 文件对应知识条目；未加入返回 404 |
| POST | `/knowledge/:id/retry` | 重试失败任务，无请求体 |
| DELETE | `/knowledge/:id` | 删除知识及处理任务，保留原文件 |

保持项目统一的 `{code,msg,data}` 响应格式：

- 首次加入和重试返回 HTTP 202。仅代表已提交，不代表正文已完成。
- 重复加入返回 HTTP 200 和原条目，不修改原标题、不重复排队。失败条目必须调用重试接口。
- 列表返回 `data.items/total/page/page_size`；不查询正文，`content` 字段为空。搜索为标题字面包含匹配，不把 `%`、`_` 当通配符。
- 状态为 `pending/running/ready/failed`。未加入和格式不支持由文件页判断，不是知识条目的持久状态。
- 详情字段包含 `source_file_id/source_file_name/source_folder_id/source_folder_name/source_type/title/content/status/error_code/error_message/imported_at/created_at/updated_at`。来源目录为提交时直接父目录的快照，不是实时完整路径。
- 错误响应：参数/格式/大小错误 400、无权限或资源不存在 404、非失败任务重试 409、内部异常 500。现有 JWT 中间件的 401 格式保持不变。
- 删除接口按当前用户限定范围，成功返回 HTTP 200 和 `data: null`；不存在或不属于当前用户的条目返回 404（2026-10 起，此前按幂等成功处理）。

## 操作日志

- 加入（仅首次创建）、删除、重试导入会写入操作日志，目标类型为 `knowledge`，动作分别为 `knowledge_add/knowledge_delete/knowledge_retry`；标题与来源目录取知识条目快照。
- 文件或文件夹删除勾选 `delete_knowledge` 级联删除知识时，不逐条写知识日志，而是在文件/文件夹的 `delete` 日志 `detail` 中增加 `knowledge_removed` 计数。
- 日志写入失败仅记服务端错误，不影响主流程；每条写入后按用户裁剪至最近 500 条。

## 删除语义

- 文件删除请求可携带 `delete_knowledge: true`，省略或为 false 时仍只软删除原文件，保留知识。
- 勾选同步删除时，文件软删除与关联知识、任务的物理删除在同一事务内完成；任一步失败全部回滚。
- 删除文件夹时覆盖子目录，也会清理这些目录内此前已软删除源文件的关联知识。
- 独立删除知识不修改原文件，不要求原文件仍存在。
- 删除时先删除任务，再删除条目；运行中的 worker 不能写回已删除任务。加入知识时锁定源文件，避免与同步删除竞态产生孤立条目。
- 未选择同步删除时，原文件已删除的未完成任务会失败，已完成正文仍可阅读。

## 处理流程

1. 校验用户拥有文件，后缀为 `.md` 或 `.markdown`（忽略大小写），元数据大小不超过 20 MiB。
2. 默认标题为去扩展名的文件名；允许自定义，长度为 1–200 个 Unicode 字符。
3. 持久化知识条目及任务。数据库唯一键处理并发重复提交，失败事务不遗留半条数据。
4. 后台单 worker 每秒检查队列，也会连续处理已排队任务。用两分钟租约领取任务，将两表状态原子更新为 `running`。
5. 按来源哈希读取文件，兼容旧 `hash.extension` 存储；使用受限根目录访问拒绝路径穿越和逃逸符号链接。
6. 实际读取同样限制 20 MiB；验证普通文件、UTF-8、无 NUL 字符，去 BOM、统一换行。全空白正文失败。
7. 原样保存 Markdown，不生成 HTML。后续前端渲染必须禁用危险 HTML 或做清洗，正文中的链接/图片不会在后端加载。
8. 完成后事务写入正文及 `ready` 状态；业务失败写入 `failed` 与公开错误原因。数据库故障或进程退出留下租约，过期后自动重新领取。

租约 token 在写结果时再次校验，旧 worker 不能覆盖新 worker 的结果。关闭服务会取消并等待后台 worker；未完成任务下次启动恢复。

## 错误与边界

公开错误码包括 `empty_content/invalid_encoding/file_too_large/source_unavailable/invalid_source/source_deleted/source_changed`，不泄漏服务器磁盘路径。

- 原文件已删除的未完成任务失败；已完成知识不依赖源文件继续存在。
- 正文格式为 UTF-8 Markdown；不执行 OCR、PDF 解析、AI 摘要、向量化或远程资源加载。
- 只允许失败任务重试。重试校验原文件仍存在、格式和大小合法且哈希与快照一致。
- 空源文件反复重试仍会失败，系统不会将其改成虚构成功。当前文件模块不提供覆盖内容功能，需要另传有效文件并创建新条目。
- 处理中的状态查询使用详情或按文件查询；本轮没有新增文件列表的批量状态联查，前端接入时可进一步优化。

## 验证

```bash
pnpm test:backend
pnpm build:backend
```

单元测试覆盖文件与用户隔离、标题/格式/大小、幂等、BOM/换行、无效编码、空文件、路径保护、旧存储路径、失败重试、状态筛选、事务回滚、租约领取及旧 worker 写入拒绝，以及删除范围、同步删除回滚、子目录关联清理和已删除源文件拒绝加入。

真实 MySQL 迁移与 HTTP 联调需在本机开发环境执行；自动化测试使用临时磁盘文件和 sqlmock，不连接或修改开发数据库。
