# RAG 检索阈值与条数配置

## 背景

对话 RAG 原先从向量库取分数最高的 5 条作为参考，不设下限：与知识库无关的问题也会强行凑满 5 条弱相关片段，模型被迫基于噪声作答。需求是相似度不达阈值视为"没搜到"，并把阈值与条数开放为用户设置。

## 结果

- `user_ai_settings` 新增 `rag_top_k`（1–50，默认 5）与 `rag_min_score`（0.05–1，默认 0.5），AutoMigrate 幂等补列，存量行由列默认值补齐。
- 检索参数只来自服务端设置：`RagQuery` 不再携带 TopK，内部检索网关忽略请求体中的 `topK`（保留字段仅为 Mastra 契约兼容），`ChatService.RagSettings` 读取设置并对越界值（含未迁移行的零值）回退默认值。
- 阈值两层生效：Qdrant 请求带 `score_threshold` 下推过滤，Go 组装 sources 时再兜底过滤（防旧集合与替身返回弱匹配）。全部低于阈值 → 空 sources → 走 Mastra 已有拒答文案"知识库中没有找到相关内容"。
- TopK 上限由 10 提高到 50；聊天 payload 中的 `top_k` 仅为与 AI 服务的一致性展示，网关会重新读取设置。
- 前端模型设置页「向量化与检索」卡片新增两个数字输入，随保存默认模型一并提交，前端先校验范围；`DefaultsPayload` 省略检索字段时后端保留已存值。
- Swagger 三文件由 `swag init` 重新生成，diff 纯增量。

## 决策与理由

- 阈值默认 0.5 而非 0：阈值的意义就是把无关问题挡在门外，默认 0 等于没修这个缺陷；代价是弱相关但有用的长尾片段也会被过滤，用户可自行调低。
- 检索参数放后端持久化而非前端 localStorage：多设备一致，且内部网关本来就不该信任请求体中的检索范围。
- 先提高 TopK 上限，"给大模型按片段读整篇文章的工具"作为后续独立特性候选：前者是安全的量变，后者需要 Mastra tool + Go 内部接口 + capability 鉴权 + 截断与成本控制，不应混进本次改动。

## 教训

- 向量库过滤要"下推 + 兜底"双写：只下推则旧数据/替身行为不可控，只兜底则候选扩容循环可能被低分占位者挤爆（topK 名额被阈值外片段占掉）。
- 测试替身按真实契约同形很关键：本次让向量 fake 故意忽略阈值，才能让 Go 侧兜底过滤真正被测试覆盖；Qdrant 侧则由请求体断言 `score_threshold` 覆盖。
- 设置读取要对存量零值宽容：迁移前创建的行在内存中是新字段零值，读取时统一回退默认值，避免把"没设置过"误判为"显式设为 0"。

## 候选特性（未实施）

- **按片段读全文工具**：当某个片段命中但上下文不足时，让大模型通过 Mastra tool 调 Go 内部接口读取整篇知识正文。需要一次性 capability 鉴权、正文截断与成本控制，单独立项。

## 验证

- 后端 `go build/vet/test ./...` 全绿；新增用例：阈值过滤与空结果拒答、越界设置回退默认值、SaveDefaults 检索字段校验与省略保留、Qdrant 请求体 `score_threshold`、chat payload `top_k` 来自用户设置。
- 前端 typecheck、lint、vitest 197 全绿；新增用例：检索参数随默认模型提交、越界输入拦截不提交。
- 未做浏览器真机验证与真实 Qdrant 联调；重启后端后 AutoMigrate 才会补列。
